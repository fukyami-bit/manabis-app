# 来校管理システム 導入手順

要件定義書: [来校管理システム要件定義.md](来校管理システム要件定義.md)

ファイル構成

| ファイル | 役割 |
|---|---|
| `gas/code.gs` | サーバ側。データの読み書きと判定ロジック |
| `gas/student.html` | 生徒用フォーム（QRから開く） |
| `gas/staff.html` | 受付画面 |
| `test/` | Node.jsで動くテスト |

---

## 1. スプレッドシートを作る

Googleドライブで新しいスプレッドシートを作る。名前は「来校管理」など分かるもので良い。
シートは手で作らなくてよい（手順4で自動生成される）。

## 2. Apps Scriptにコードを貼る

スプレッドシートのメニューから **拡張機能 → Apps Script** を開き、3つのファイルを作る。

| Apps Script上のファイル名 | 貼り付ける内容 |
|---|---|
| `コード.gs`（既定のファイル） | `gas/code.gs` の全文 |
| `student.html`（HTMLファイルとして追加） | `gas/student.html` の全文 |
| `staff.html`（HTMLファイルとして追加） | `gas/staff.html` の全文 |

HTMLファイルは「ファイルを追加 → HTML」で作る。**ファイル名は `student` / `staff` のままにする**
（`code.gs` がこの名前で読み込む）。

## 3. 合言葉を設定する

Apps Scriptの **プロジェクトの設定 → スクリプト プロパティ** で追加する。

| プロパティ | 値 |
|---|---|
| `TOKEN` | 受付画面を開くための合言葉。推測されにくい文字列にする |

この合言葉は受付画面のURLに入る。**生徒用のQRには入らない**ので、生徒に見られても受付画面は開けない。

> スプレッドシートを別に分けたい場合のみ、`SHEET_ID` にそのスプレッドシートのIDを設定する。
> 通常は不要（Apps Scriptを開いたスプレッドシートが使われる）。

## 4. 初期セットアップを実行する

Apps Scriptのエディタで関数 `setup` を選んで実行する。初回は権限の確認が出るので許可する。

4つのシートが作られる。

| シート | 内容 |
|---|---|
| `来校ログ` | 来校の記録。**追記型で、日次のクリアは不要** |
| `生徒名簿` | 生徒番号・氏名・氏名カナ・学年・高校名の5項目のみ |
| `来校予約` | 本部システムの予約 |
| `設定` | 遅刻・要電話の基準（既定60分）、ブースの範囲 |

## 5. ウェブアプリとしてデプロイする

**デプロイ → 新しいデプロイ → 種類にウェブアプリ** を選ぶ。

| 項目 | 設定 |
|---|---|
| 次のユーザーとして実行 | 自分 |
| アクセスできるユーザー | **全員** |

「全員」にしないと、生徒のスマホからフォームが開けない。

デプロイすると `https://script.google.com/macros/s/.../exec` という形のURLが出る。

| 用途 | URL |
|---|---|
| **生徒用フォーム** | `https://script.google.com/macros/s/.../exec` |
| **受付画面** | `https://script.google.com/macros/s/.../exec?p=staff&k=合言葉` |

受付画面の「データ」タブに生徒用URLが表示されるので、そこからコピーできる。

> コードを直したときは、**デプロイ → デプロイを管理 → 編集 → バージョンを「新バージョン」** にして
> 更新する。URLは変わらないのでQRコードは作り直さなくてよい。

## 6. QRコードを作って掲示する

生徒用フォームのURLをQRコードにして校舎に掲示する。QRコードは無料の生成サービスで作れる。

設置場所は未決（要件定義書 U-1）。生徒がブースを選んでから番号を入力する流れになるので、
**入口よりカウンター付近の方が流れに合う**可能性がある。運用を見て決める。

## 7. 名簿と予約を取り込む

受付画面の **データ** タブから行う。

どちらも **ファイルを選ぶ**か、**本部システムの画面をコピーして貼り付け欄に貼る**かを選べる。
来校予約はファイル出力が無いので、貼り付けを使う。

1. **生徒名簿の取り込み** — 顧客情報一覧のファイル、または画面をコピーして貼り付け。
   **この端末から出るのは生徒番号・氏名・氏名カナ・学年・高校名の5項目だけで、
   保護者氏名・住所・電話番号・生年月日は送信されない。**
2. **来校予約の取り込み** — 画面をコピーして貼り付け欄に貼る。
   同じ予約日の分は置き換わるので、日中に貼り直しても二重にならない。
   貼った表に予約日の列が無い場合は、欄で指定した日付が使われる。

貼り付けたら **「貼り付けた内容を確認する」** を押す。どの列をどの項目として読んだかと
先頭3件が表示されるので、正しければ **「この内容で取り込む」** を押す。

列は見出し名で判定し、見出しが無ければ中身から推定する（生徒番号は行ごとに異なる数字の列、
予約時刻は時刻として読める列、など）。そのため本部システムの画面の列の並びが変わっても動く。

名簿は生徒の入会・退会があったときに取り込み直す。予約は毎日取り込む。

## 運用の流れ

```
朝       受付画面のデータタブから、本日の来校予約を取り込む
         （名簿は変更があったときだけ）

開館中   生徒がQRを読んでフォームを送信 → 受付画面に即座に出る
         スタッフは「ファイル未配布」の一覧を見て受講ファイルを渡し、
         渡したらボタンを押す

         受付が無人のときは生徒がそのまま着席するので、
         あとから未配布の一覧とブース番号を見て席まで届ける

         「未来校」タブで要電話の生徒を確認し、本部システムで
         電話番号を検索して架電する

閉館後   「次回予定」タブの自習者の次回来校予定を、
         本部システムに予約として入力する
         来なかった生徒を「未来校」タブから欠席・無断欠席で登録する

         ★クリア作業は不要。ログは追記されていくだけ
```

## 判定の基準を変える

受付画面の **データ** タブ、または `設定` シートで変更できる。

| キー | 既定 | 意味 |
|---|---|---|
| `遅刻とみなす遅れ(分)` | 60 | 予約時刻からこの時間を超えて登録されたら「遅刻」にする |
| `要電話とする遅れ(分)` | 60 | 予約時刻からこの時間を超えて未来校なら「要電話」にする |
| `ブース範囲` | `1-2,3-70,71-90,101-120` | フォームで受け付けるブース番号の範囲 |

ブースの増減があったときは `ブース範囲` を直す。
`gas/student.html` の案内文と範囲チェックも合わせて直す必要がある。

## 不具合が起きたとき

要件定義書 7.3 のとおり、**現行のExcelマクロ版に戻す**。

```
① 生徒名簿を貼り付ける
② 来校予約を貼り付ける
③ 「本日の来校情報をクリア」を必ず実行する   ← 省略すると業務が成立しない
④ 白紙の来校カードを配布する
```

③を飛ばすと、前回使った日のG〜J列が残っているため `生徒登録` マクロが対象生徒を
検索できず、要電話アラートも出ない。

そのため**白紙の来校カードを少量、在庫として残しておく**。Excelのワークフローは
カードへの記入を前提にしているため、カードがないと受付が回らない。
